# ECG Analyzer v1.0.0 — registro y adquisición por convolución

Actualización del proyecto v0.10.0. React, Electron, FastAPI, Arduino Mega/AD8232 y MongoDB local. Sin inicio de sesión. Sin mensajes «Modo de desarrollo» en la interfaz. Conserva identificación del origen (simulación, banco o experimental), avisos LO y de alimentación, y carácter no diagnóstico. Acepta nombre completo o código, con búsqueda local por nombre. No incorpora cifrado ni control de acceso propio: registra nombres reales solo con autorización, en un equipo protegido y de acceso restringido. Prefiere datos ficticios o códigos en demostraciones. No publiques datos de pacientes, respaldos, imágenes ni exportaciones en GitHub. No se ha validado seguridad eléctrica ni calidad fisiológica.

## Actualizar la aplicación instalada (Windows 10/11 x64)
1. Realiza un respaldo y cierra la app. Conserva tu versión anterior y su instalador.
2. Descomprime este ZIP en una carpeta nueva. Ejecuta `generar-actualizacion.cmd` con doble clic. El script sincroniza dependencias y empaqueta Python, React y Electron. Resultado esperado: `release/ECG-Analyzer-Setup-1.0.0-x64.exe`. Mantiene appId `org.ecganalyzer.lab`, selección de carpeta, icono y accesos directos. Instala sobre la misma ubicación anterior.
3. MongoDB Community se instala por separado; no se borra ni migra automáticamente ninguna base. Esquemas antiguos incompatibles necesitan migración independiente. Verifica en Configuración el nombre de la base de datos. Para pruebas, desde PowerShell en la carpeta del proyecto: `$env:ECG_MONGO_DB='ecg_database_v100_prueba'` y ` .\iniciar-desarrollo.cmd`. Para desarrollo, primero `instalar-desarrollo.cmd` si faltan dependencias. Electron inicia Python automáticamente en loopback con token efímero. No se requiere abrir Chrome ni Uvicorn manualmente.

## Adquisición física y firmware
Inicio predeterminado: 100 Hz, 1,000 muestras, 10 segundos. Dos botones de adquisición: Simular ECG y Adquirir señal real. Detener permanece como control de captura. Una captura física fallida nunca genera muestras sintéticas. El diálogo de verificación sigue siendo desplazable. Cierra Arduino IDE y cualquier monitor serial antes de usar la app. Se conserva la confirmación de seguridad externa, consentimiento y batería; la batería no garantiza aislamiento. Usa simulador físico ECG para pruebas sin personas. Para adquisición experimental en personas se requiere validación documentada del equipo por personal competente y consentimiento.

- Para adquisición supervisada: carga `firmware/ECG_Mega/ECG_Mega.ino` con la placa Arduino Mega 2560. Ahora FS=100 (10 ms), A0, 115200 baudios, LO+ D10 y LO- D11. No cambia el cableado. El protocolo ECG/1 usa HELLO/START/STOP y transmite secuencia, tiempo, ADC y LO. Selecciona 100 Hz en la interfaz. Verificación independiente de banco: ` .\.venv\Scripts\python.exe backend\verificar_arduino.py --port COM8 --fs 100`.
- El firmware anterior de 250 Hz sigue funcionando seleccionando 250 Hz; no hay necesidad de cambiarlo para seguir usando esa frecuencia. Se puede compilar el firmware nuevo con FS=250 si se desea. Para verificar: usa `--fs 250`.
- El sketch de referencia incluido en `firmware/ECG_Original_Banco/ECG_Original_Banco.ino` transmite solo `Serial.println(analogRead(A0))` con `delay(10)` y es compatible a 100 Hz nominales. Es el formato predeterminado al abrir Adquirir señal real a 100 Hz; comprueba Prueba de banco y formato Original: solo ADC (sin LO). No envía HELLO ni START, descarta la primera línea potencialmente incompleta, acepta ADC entero o formato exacto 0,1023,ADC. No confunde LO con amplitud. Solo banco sin personas: no tiene LO, secuencia ni reloj de muestras; tiempos y FFT aproximados, no se verifica pérdida de muestras ni frecuencia real. No se permite seleccionar este formato para adquisición experimental en personas.
- En el firmware ECG/1, PLOT envía solo A0 durante 60 s (solo banco). STOP detiene. HELLO restablece el protocolo completo.
- El modo experimental detiene la captura si LO alto, fallo serial o pérdida de muestras. Se visualizan las muestras parciales como incompletas, no se guardan como completas. La prueba de banco conserva muestras con avisos LO y las identifica como no clínicas.

## Procesamiento y visualización
Se utiliza exclusivamente la convolución discreta de la referencia con kernel de media móvil uniforme (10 muestras por defecto, ajustable entre 2 y 50). El resultado completo de la referencia tiene N+M-1 valores; aquí se conserva solo el intervalo capturado y se omiten M-1 valores iniciales sin ventana completa, para no dibujar transitorios artificiales ni muestras no adquiridas. Se mantiene el vector original intacto. La vista Separadas presenta escalas verticales independientes. Se retiran Notch, Butterworth y otros filtros de nuevas adquisiciones y del endpoint de análisis. FFT sigue disponible como análisis opcional, no filtro; no representa la frecuencia cardíaca. Los estudios antiguos se conservan y se identifican por su filtro histórico; pueden reprocesarse con convolución. A 100 Hz el filtro de 10 muestras puede atenuar considerablemente QRS; no es diagnóstico. Los valores ADC no están calibrados en mV. La captura física no garantiza que la señal sea fisiológica.

## Historial, exportaciones y respaldos
Conserva MongoDB, guardado PNG, exportaciones PDF y CSV, búsqueda, reapertura de estudios y respaldo/restauración independiente. Los archivos .ecgbackup no están cifrados; guárdalos en lugar privado. El respaldo no sustituye un plan profesional; no incluye GridFS u otras colecciones ajenas a pacientes/estudios. Evita escrituras externas durante respaldo. Restaurar crea ecg_restore_<uuid> y no reemplaza la base original; esquemas incompatibles pueden requerir migración. La selección de base restaurada es temporal. Los scripts de MongoDB Database Tools son opcionales y requieren sus herramientas instaladas.
